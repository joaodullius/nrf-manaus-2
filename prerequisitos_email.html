Pré-requisitos de software — instalar no notebook antes do curso

Versões conferidas na bancada de preparação em 08/09/2026. Onde não há versão fixa, vale a versão atual.

Base (todos os módulos)

  1. Visual Studio Code (versão atual) com a extensão nRF Connect for VS Code Extension Pack (versão atual, pelo marketplace do VS Code).
  2. nRF Connect SDK v3.4.0 e toolchain v3.4.0, instalados pela própria extensão: painel nRF Connect → Install Toolchain → v3.4.0; depois Manage SDKs → v3.4.0. Caminho sugerido: C:\ncs\v3.4.0.
  3. nRF Util (nrfutil) 8.2.0 ou mais novo, com os comandos device e sdk-manager instalados (nrfutil install device sdk-manager).
  4. SEGGER J-Link — a versão que o toolchain instala; aceitar a instalação dos drivers quando pedido.
  5. nRF Connect for Desktop (versão atual) com os apps Programmer, Serial Terminal, Power Profiler e Board Configurator.
  6. Python 3.12 (3.11 também serve), com pip no PATH.
  7. Git (com Git Bash).

Módulo Edge AI

  1. Edge AI Add-on v2.3.0 para o nRF Connect SDK. Ele é um workspace west separado, que baixa uma cópia própria do NCS v3.4.0 (alguns GB — fazer em rede boa, antes do curso). Instalar no mesmo nível do v3.4.0, em C:\ncs\sdk-edge-ai, para ficar assim: 
    C:\ncs\
├── v3.4.0\          (NCS dos módulos de comunicação)
├── sdk-edge-ai\     (workspace do Edge AI Add-on)
└── toolchains\

    Pelo VS Code: painel nRF Connect → Create a new application → Browse nRF Connect SDK Add-on Index → Edge AI Add-on v2.3.0 → pasta de destino nova C:\ncs\sdk-edge-ai. O west update continua em segundo plano por vários minutos depois do clone; esperar terminar antes de compilar.

    Por linha de comando (numa pasta nova e vazia — nunca dentro de C:\ncs\v3.4.0):

    nrfutil sdk-manager toolchain launch --ncs-version v3.4.0 --terminal
mkdir C:\ncs\sdk-edge-ai && cd C:\ncs\sdk-edge-ai
west init -m https://github.com/nrfconnect/sdk-edge-ai --mr v2.3.0
west update

Módulo de Comunicação — Wi-Fi 6

  1. Blobs de firmware do nRF70, uma vez por instalação do SDK. No terminal do nRF Connect (nRF Connect: Open Terminal no VS Code): 
    west blobs fetch nrf_wifi
    A extensão do VS Code não faz isso sozinha; sem os blobs nenhum build de Wi-Fi compila. Conferir com west blobs list nrf_wifi.
  2. protoc (Protocol Buffers compiler) 25.3 ou mais novo, no PATH — lab de provisionamento.
  3. mosquitto 2.x (broker MQTT) — lab de HTTP/MQTT. Depois de instalar, desativar o serviço automático que o instalador cria (PowerShell como administrador): 
    Stop-Service mosquitto
Set-Service mosquitto -StartupType Manual
    O lab sobe o broker próprio.
  4. Regras de firewall do Windows, em PowerShell como administrador, para os servidores dos labs receberem conexão do kit (a rede tem de estar classificada como Particular): 
    New-NetFirewallRule -DisplayName "nrf-manaus lab9 TCP"   -Direction Inbound -Protocol TCP -LocalPort 9000 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "nrf-manaus lab10 HTTP" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "nrf-manaus lab10 MQTT" -Direction Inbound -Protocol TCP -LocalPort 1883 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "nrf-manaus lab12 UDP"  -Direction Inbound -Protocol UDP -LocalPort 5001 -Action Allow -Profile Private
    Se em algum momento o Windows perguntou sobre acesso de rede para o Python e alguém clicou em Cancelar, existe uma regra de bloqueio por programa que vence as regras acima; remover antes.
